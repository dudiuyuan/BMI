# DTW 使用说明

程序使用 Python 3.10 或更新版本，不需要安装第三方库。运行时直接填写参数，没有算法模式；不填的惩罚参数默认为 0，也就是关闭。新实验默认做逐基因幅度归一化，下游默认使用徐秋凡的 k-medoids（`xqf`）聚类。

## 1. 现在默认对变化幅度做归一化

`dtw.py` 会先对每条基因减去自身平均值，再做带下限的标准差缩放，然后计算 DTW。普通算式是：

```text
处理后的表达值 = (输入表达值 − 这条基因的平均值)
               ÷ max(这条基因的标准差, scale_floor)
```

标准差使用总体标准差，也就是“各时间点与均值之差的平方，取平均后开平方”。默认 `scale_floor=0.1`。

- 标准差大于等于下限时，去掉整体幅度尺度，缩放后的标准差为 1。
- 标准差小于下限时，用下限作分母，避免把平坦基因的微小噪声过度放大；这类曲线仍保留较小的波动。
- 常数曲线减去均值后整条为 0。
- `--scale-floor 0` 关闭这一步，直接使用输入文件中的值。

例如 `[1, 2, 3]` 与 `[12, 14, 16]` 只差基线和幅度，归一化后会得到相同的曲线。`[-0.01, 0, 0.01]` 用默认下限处理后是 `[-0.1, 0, 0.1]`，不会强行放大到标准差为 1。

0.1 是当前初始设置，不代表所有数据的最佳下限。它和输入表达量使用相同单位；换数据或输入尺度时，需要重新评估。每条基因独立计算，不使用真实类型，也不受其他基因是否被选入实验影响。

数据准备文件夹提供的三种文件分别是：

| 文件 | 上游已经做过什么 |
| --- | --- |
| `raw_imputed.csv` | 填补缺失值，尚未中心化或缩放 |
| `centered.csv` | 每条基因减去自身平均值，仍保留幅度差异 |
| `zscore.csv` | 减均值，再除以自身标准差 |

新实验建议输入 `centered.csv` 或 `raw_imputed.csv`。如果输入已经做过 z-score 的数据，原先被放大的低幅度噪声不会被这一步自动恢复。

输入 CSV 不会被改写，也不另存一份归一化数据。实际处理方式和下限保存到 `run.json`；诊断曲线、路径以及单对输出中的表达值，都使用与计算距离相同的数值。

旧实验（包括 demo 和 1119_01～1119_26）沿用当时的处理记录，不会因为默认值改变而被重新归一化。直接调用底层 `dtw.py` 的 `align` 时，需要自己传入处理后的数组；它不会重复归一化。

## 2. 程序怎么算代价？

最终代价由两部分组成：匹配点的代价，以及沿路径移动时的拉伸惩罚。

### 时间差怎么算

程序先把两条序列的时间坐标放到同一个 0 到 1 的范围内：

```text
归一化时间 = (当前时间 − 两条序列中最早的时间) ÷ 两条序列共同覆盖的总时长
时间差 = 两个归一化时间之差的绝对值
```

例如，观测范围是 0 到 120 分钟，那么相差 24 分钟对应的时间差就是 0.2。只有一个共同时间点时，时间差为 0。

运行 CSV 时，时间来自 `t0`、`t20` 等列名。直接调用 Python 的 `align` 而不提供时间时，每条序列会各自按等间隔放到 0 到 1。

这一步只改变时间坐标；表达量已经按第 1 节的方式单独处理。

### 一个匹配点的代价

```text
表达差异 = (基因 A 当前点的表达值 − 基因 B 当前点的表达值)²
时间惩罚 = time_penalty × 时间差的 power 次方

一个匹配点的代价 = 表达差异 + 时间惩罚
```

当前实验保持 `dynamics=0`，不启用速度增强，也没有加入斜率匹配项。`time_penalty=0` 时，整个时间惩罚为 0。

为了读取旧实验，原有 `dynamics` 参数仍保留：非零时，它会把时间惩罚乘以“1 + dynamics × 两个点变化速度的平均值”。这里的速度取绝对值，内部点用前后两点差分，端点用单侧差分，单点为 0。本次改动不使用这项。

### 一段拉伸的代价

对角步表示两条序列各向前走一个点。水平或垂直步表示一条序列向前走，另一条停留在原来的点，也就是发生拉伸。

连续朝同一个方向走的水平或垂直步算一段拉伸。遇到对角步，或者从水平改为垂直、从垂直改为水平，当前段就结束。

```text
一段拉伸的惩罚 = 这段的步数 × step_penalty
               + open_penalty
               + (这段的步数 − 1) × extend_penalty
```

也就是每一步都收步惩罚，第一步另收开启惩罚，从第二步起另收延伸惩罚。这三项可以同时使用，直接相加。

例如，连续拉伸 3 步，参数分别是：

```text
step_penalty   = 0.1
open_penalty   = 0.2
extend_penalty = 0.05

这一段的惩罚 = 3 × 0.1 + 0.2 + 2 × 0.05 = 0.6
```

水平和垂直步仍然会匹配表达点，仍要收取那个匹配点的代价，不表示删除一个点。

### 整条路径和最终距离

```text
一条路径的总代价 = 路径上所有匹配点的代价之和 + 所有拉伸段的惩罚之和

cost = 从第一个点对走到最后一个点对，所有允许路径中最小的总代价
distance = 对 cost 开平方
```

距离矩阵里保存的是 `distance`，不除以路径长度。

如果开启窗口，路径上的每个匹配点还必须满足“时间差不超过 window”。`window=0` 表示关闭窗口限制。

## 3. 各个参数是什么意思？

命令行里的参数用连字符，例如 `--time-penalty`；Python 和 `run.json` 里用下划线，例如 `time_penalty`。它们是同一个参数。

| 命令行参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--step-penalty` | 0 | 每个水平或垂直步收多少额外代价。越大，越不愿意拉伸 |
| `--open-penalty` | 0 | 每开启一段拉伸收多少额外代价。越大，越不愿意开启新段 |
| `--extend-penalty` | 0 | 一段拉伸从第二步起，每步收多少额外代价。越大，越不愿意连续拉伸很长一段 |
| `--time-penalty` | 0 | 时间惩罚的权重。越大，越不愿意匹配时间相距较远的点 |
| `--dynamics` | 0 | 原有速度增强项，本次保持关闭；兼容旧记录 |
| `--power` | 2 | 时间差的指数。默认就是时间差的平方；必须大于 0，不是开关 |
| `--window` | 0 | 最多允许相差多少比例的观测时长。例如 0.2 表示允许相差总时长的 20%；0 表示不限制 |

输入处理和下游聚类另有两个选项：

| 命令行参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--scale-floor` | 0.1 | 逐基因缩放时的标准差下限；正值开启带下限的幅度归一化，0 关闭这一步，不能为负 |
| `--clustering` | xqf | 诊断使用的聚类方法，可选 xqf（徐秋凡的 k-medoids）、kmedoids（PAM）或 average；只影响分组，不影响 DTW 距离 |
| `--clustering-seed` | 42 | 仅 `--clustering xqf` 使用的随机种子，保存进 `run.json` |

使用时注意：

- 惩罚参数都不能为负，设为 0 就关闭对应收费。只填开启惩罚，延伸惩罚仍为 0。
- 所有参数都必须是有限数值，不能是无穷大或 NaN。
- `window` 范围是 0 到 1。开启后，正值越小限制越严格；设为 1 允许全部点对。
- `power` 不是越大惩罚就越重。时间差在 0 到 1 之间，因此固定其他参数时，增大指数会降低中间位移的惩罚，使惩罚更集中在大位移上。
- 现在 `window=0` 表示关闭限制。需要只匹配共同时间点时，可对当前离散时间网格使用很小的正数，例如 `0.000000001`；两条时间轴不一致时可能找不到完整路径。

## 4. 怎么运行？

在本 README 所在的 DTW 文件夹中运行。以下命令只是示例，输入路径和实验名称按需要修改。

所有惩罚关闭，运行幅度归一化后的标准 DTW：

```bash
python3 dtw.py --input '../数据准备/outputs/simulated/baseline/processed/centered.csv' --output outputs/实验名称
```

需要什么惩罚就直接填写，不需要的可以省略：

```bash
python3 dtw.py --input '../数据准备/outputs/simulated/baseline/processed/centered.csv' --scale-floor 0.1 --open-penalty 2 --extend-penalty 0.5 --output outputs/另一组参数
```

这个配置在本次 baseline 上得到 ARI=1，在 challenge 上得到约 0.175，可作为继续研究的起点；不代表通用最佳参数。dynamics 保持为 0。归一化改变了表达差异的尺度，因此惩罚数值也需要一起重新评估。每次实验使用新的输出目录，避免覆盖已有结果。

一次完整实验输出两个文件：

- `distance_matrix.csv`：所有基因两两之间的距离。
- `run.json`：实际 DTW 参数、幅度处理方式、缩放下限、默认聚类方法、输入路径和校验信息。

加上 `--pair 基因A 基因B`，就只计算这对基因，输出 `alignment.csv`、`alignment.svg` 和 `run.json`。

其他可选参数：

- `--config-file 已有实验/run.json`：完整复用该次 DTW 参数、表达预处理和默认聚类方法，优先于对应命令行选项。旧记录没有预处理字段时，按当时的“输入值不变”处理；没有聚类字段时沿用平均连接。只包含 Config 参数的 JSON 对象仅覆盖 DTW 参数，表达处理和聚类仍使用命令行设置。
- `--limit N`：只使用输入的前 N 条基因，不生成新数据。
- 基因数没有上限，直接计算完整距离矩阵。基因很多时会比较慢：DTW 的计算量随基因数的平方增长，GSE3635 全部 6000 多条基因约 1800 万对。

旧记录里的 `method` 字段不再参与运行；窗口、开启和延伸参数的 null 按 0 读取。旧记录中显式写了 `window=0` 的，窗口含义已发生上述变化；现有 demo 的窗口是 null，不受影响。

## 5. 怎么查看自己的实验结果？

```bash
python3 diagnose.py outputs/实验名称 --k 6
```

这里 `--k 6` 表示分成 6 个簇。程序读取已有距离矩阵，按 `run.json` 保存的方法聚类，然后在该目录写入 `diagnose.html`。新实验默认使用徐秋凡的 k-medoids（`xqf`），旧实验没有相关记录时仍使用平均连接。网页会明确写出聚类方法和表达值如何处理。

k-medoids 从真实基因中选择 6 个代表，尽量减小各基因到最近代表的总距离。实现使用确定性的 PAM BUILD + SWAP，不读取标签，不强制各簇人数相等；结果是一种局部最优分组，不保证全局最优。

可以显式指定 `--clustering average` 或 `--clustering kmedoids` 来对照同一张距离矩阵。每次运行会更新该目录的 `diagnose.html`；希望同时保留两份报告时，请先分别保存为两个实验目录。本次两项改动的单独对照保存在 1119_27～1119_32，归一化后的参数对照与复查保存在 1119_33～1119_37。完整结果见 [本轮实验汇总](outputs/1119_normalization.md)。

诊断图显示计算 DTW 时真正使用的表达值。归一化实验显示归一化后的曲线，旧实验显示当时输入的曲线。

诊断不会自动生成数据、运行测试或做参数对照，也不会重新计算整张距离矩阵。它只为少量邻居补充对齐路径，并检查是否与原距离一致；代码或费用不匹配时，不展示对应路径。

真实类型默认从输入附近的 `ground_truth.csv` 读取，按 `gene_id` 对应。可以用 `--truth 路径` 指定标签文件，或用 `--label-column shape_cluster` 切换标签列。当前类型诊断需要真实标签，不适用于没有标签的 GEO 全量数据，最多支持 500 条基因。

报告只展示这次实验的结果。修改参数后，需要自己运行一个新实验，再诊断那个实验；旧结果和旧报告不会自动变化。簇数由你指定，不能只凭一份报告认定最佳参数。

## 6. 文件分别做什么？

| 文件或目录 | 用途 |
| --- | --- |
| `dtw.py` | 核心算法、参数定义，以及按你指定的输入和参数运行实验的命令行 |
| `dtw_modes.py` | 四种固定的 DTW 变体：选模式即可，不用手动填参数 |
| `euclidean.py` | 欧氏距离基线：输入、预处理、输出与 `dtw.py` 相同 |
| `pearson.py` | 皮尔森相关距离（1 − r）基线：输入、预处理、输出与 `dtw.py` 相同 |
| `support/baseline_runner.py` | 两个基线共用的命令行 |
| `tune_dtw.ipynb` | 调参 notebook：在带真标签的模拟数据上比较 DTW 参数，输出推荐参数 |
| `diagnose.py` | 查看已有实验的聚类、曲线和对齐 |
| `outputs/` | 你主动运行的实验结果 |
| `support/` | 诊断使用的辅助代码和网页模板 |
| `tests/` | 自动测试 |

需要检查程序时，可以手动运行：

```bash
python3 -B -m unittest discover -s tests -v
```

测试使用临时目录，不往 `outputs` 写结果。


## 接入徐秋凡的 k-medoids（`--clustering xqf`）

`support/xqf_adapter.py` 直接读取仓库里的 `xqf/xqf_clustering/k_medoids.py`，不复制她的代码；她更新文件后这里自动使用新版本。她的算法是随机多起点（默认 `n_init=5`、`max_iter=100`）的交替式 k-medoids，结果取决于随机种子。

```bash
# 对已有实验重新分组（不重算 DTW 距离）
python3 diagnose.py outputs/1119_02 --k 6 --clustering xqf --seed 42
# 新实验默认就用她的聚类
python3 dtw.py --input centered.csv --output outputs/new_run --clustering xqf --clustering-seed 42
```

适配层先用本项目的规则检查距离矩阵，再交给她的函数；如果有基因没被分进任何簇，会直接报错而不是输出错误分组。


## 对照方法：欧氏距离和皮尔森相关距离

`euclidean.py`、`pearson.py` 与 `dtw.py` 的上下游完全相同：读同一种输入 CSV，做同样的逐基因归一化（默认 `--scale-floor 0.1`），输出同样的 `distance_matrix.csv` 和 `run.json`，再由同一个 `diagnose.py` 和同一套聚类（默认徐秋凡的 k-medoids）处理。只有两两距离的算法不同：

| 方法 | 距离 | 特点 |
| --- | --- | --- |
| DTW | 允许时间对齐后，差值平方和的最小值再开方 | 能把错开的峰对齐 |
| 欧氏距离 | 同一时间点差值平方和再开方 | 不做时间对齐；等于 DTW 只走对角线时的距离 |
| 皮尔森 | 1 − 相关系数 r（0 = 形状相同，2 = 正好相反） | 只看形状，忽略基线和幅度；平坦曲线与平坦曲线记 0，与非平坦曲线记 1 |

```bash
python3 dtw.py       --input centered.csv --output outputs/run_dtw
python3 euclidean.py --input centered.csv --output outputs/run_euclidean
python3 pearson.py   --input centered.csv --output outputs/run_pearson
python3 diagnose.py outputs/run_pearson --k 6
```

基线没有 DTW 参数和对齐路径，诊断网页会注明这一点。`run.json` 中的 `distance_method` 记录方法；没有这一字段的旧实验都是 DTW。

诊断时不再比对整个代码文件的指纹：每条预存路径都会用当前代码重算，费用与保存的距离一致才显示，不一致的那一对不显示并给出提示。

## 加速选项（备选，默认关闭）

`dtw.py` 只计算窗口以内的格子（默认就是这样，结果与以前完全相同）。另外有两种可选加速，用 `--prune` 打开，只作用于完整距离矩阵，`--pair` 模式不受影响：

| `--prune` | 做什么 | 距离会不会变 |
| --- | --- | --- |
| `none`（默认） | 不加速 | — |
| `cells` | 格子跳过：每对基因的 DP 表里，累计代价加上剩余行的 LB_Keogh 下界已经超过对角线路线代价的格子不再计算 | 完全不变，最优路线也不变 |
| `pairs` | 整对跳过：先用 LB_Keogh 下界判断，下界超过阈值的基因对不算；计算中途确定会超过阈值的提前终止 | 超过阈值的距离记为阈值，即 min(DTW 距离, 阈值) |
| `both` | 同时使用以上两种 | 同 `pairs` |

`pairs`/`both` 的阈值二选一：

- `--prune-threshold 数值`：直接给距离阈值。
- `--prune-quantile q`（默认 0.9）：随机抽 `--prune-sample` 对基因（默认 2000，固定种子），取精确距离的第 q 分位数作阈值。0.9 表示大约最远的 10% 基因对会被截断。

阈值不能太小：被截断的基因对一律“一样远”，聚类会分不清它们。`run.json` 的 `pruning` 记录实际阈值，以及下界跳过、提前终止、完整计算的基因对数；`--config-file` 复用时沿用同一个阈值。诊断网页会注明截断，被截断的基因对不会触发“距离不一致”的提示。

## 调参（`tune_dtw.ipynb`）

在 `zrz/dtw` 文件夹里用 Jupyter 打开，从上到下运行。第一格设置数据（默认 wpj 的 baseline）、结果目录（默认 `outputs/tuning_baseline`）和聚类种子数（默认 20）；「第 1 轮」那一格列出要试的参数，可直接修改。

流程：标准 DTW 和每个参数单独试几个强度 → 每类参数（窗口 / 拉伸惩罚 / 时间惩罚）取最好的值做组合 → 欧氏、皮尔森作参照。每个距离矩阵用徐秋凡的 k-medoids 跑多个种子取平均，同时按 `true_cluster`（k=6）和 `shape_cluster`（k=5）打分。

结果目录里有 `results.csv`（全部配置）、`summary.md`（排名表）和 `recommended.json`（推荐参数及 `dtw.py` 命令行），在 baseline 上约需 1–2 分钟。

## 四种固定变体（`dtw_modes.py`）

最终交付用这四种模式，不需要手动填参数：

```bash
python3 dtw_modes.py --mode time                   --input centered.csv --output outputs/<name>
python3 dtw_modes.py --mode time-dynamics          --input centered.csv --output outputs/<name>
python3 dtw_modes.py --mode diagonal-time-dynamics --input centered.csv --output outputs/<name>
python3 dtw_modes.py --mode diagonal-time          --input centered.csv --output outputs/<name>
python3 dtw_modes.py --list                        # 查看每种模式对应的参数
```

| 模式 | 含义 | 参数（都不缩放，`--scale-floor 0`） | 候选组 |
| --- | --- | --- | ---: |
| `time` | 时间惩罚 | 时间惩罚 2 | 3 |
| `time-dynamics` | 时间惩罚 + 表达变化速率 | 延伸 0.05、时间惩罚 0.5、速率 0.3 | 8 |
| `diagonal-time-dynamics` | 对角线窗口 + 时间惩罚 + 表达变化速率 | 窗口 0.25、延伸 0.05、时间惩罚 0.5、速率 0.3 | 6 |
| `diagonal-time` | 对角线窗口 + 时间惩罚 | 窗口 0.1667、延伸 0.05、时间惩罚 2 | 1 |

“对角线窗口”就是 `--window`：把匹配路径限制在对角线附近。候选组编号对应 `outputs/final_candidates/`。

计算完全由 `dtw.py` 完成，结果与在 `dtw.py` 中写出同样参数完全相同；`run.json` 多一个 `variant` 字段记录模式名。DTW 参数和 `--scale-floor` 由模式固定，不能再指定；其余 `dtw.py` 选项照常可用（`--clustering`、`--limit`、`--pair`、`--prune` 等）。需要其他参数时仍用 `dtw.py`。

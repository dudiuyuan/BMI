# 1119 幅度归一化与聚类方式对照

本轮落实两项改动：逐基因幅度归一化、k-medoids 聚类。没有启用 dynamics，也没有增加斜率匹配项。

归一化算式：处理值 = (输入值 − 自身均值) ÷ max(自身总体标准差, 0.1)。这次 0.1 是预先设置的初始下限，不是根据 challenge 标签筛出的最佳值。

输入均为已有 centered.csv；第一轮单独对照固定 open_penalty=0.2、extend_penalty=0.05、power=2，其余 DTW 惩罚为 0；后续参数见补充表。全部实验固定 6 簇和 true_cluster 评价。

每份数据都有四种组合：原流程、只换聚类、只加归一化、两者都改。只换聚类直接复用同一张距离矩阵；平均连接与 k-medoids 的归一化对照也使用完全相同的距离矩阵。原实验和报告保持原样。

## 归一化改变了什么

平均连接与 k-medoids 只是对同一张距离矩阵作不同分组，因此同一输入处理方式的最近邻比例必然相同。比较原流程与只换聚类，检查下游影响；比较原流程与只加归一化，检查输入幅度处理的影响。

低于下限的曲线不会被强制拉到标准差为 1；常数曲线归一化后为 0。诊断图和匹配路径使用与实际距离计算相同的表达值，并在网页中写明处理方式。

PAM 使用确定性的 BUILD + SWAP，不使用标签、不强制簇大小相等。标签仅在聚类后用于评价。

## 运行方式

新实验默认开启这次幅度归一化，并默认使用 k-medoids。示例：

```bash
python3 run_dtw.py --input '../数据准备/outputs/simulated/baseline/processed/centered.csv' --scale-floor 0.1 --open-penalty 2 --extend-penalty 0.5 --output outputs/新的实验名称
python3 diagnose.py outputs/新的实验名称 --k 6
```

scale-floor=0 关闭新增归一化；clustering=average 可保留平均连接。直接读取旧 run.json 时仍完整复用旧预处理与聚类约定。

## 本轮结论与当前建议

本轮共新增 11 个实验（1119_27～1119_37），每个目录都保存了距离矩阵、实际参数和 diagnose.html。

1. 聚类方式是之前问题的重要组成部分。在同一张未做幅度缩放的距离矩阵上，只换成 k-medoids，就让 baseline 的 ARI 从 0.8107 提高到 1.0000。这个改善不需要修改 DTW 递推，也没有强制每簇 25 条。
2. 幅度归一化本身不保证分数上升。沿用原来的 0.2/0.05 惩罚时，归一化加 k-medoids 的 baseline ARI 是 0.8045。归一化改变了局部表达代价的数值尺度，需要重新评估惩罚强度。
3. 归一化后，增强开启／延伸惩罚到 2/0.5 的 1119_35，以及保留 0.2/0.05 并加入时间惩罚的 1119_33、1119_34，都让 baseline 六类完全分开。没有启用 dynamics，也没有增加斜率匹配项。

当前可以把 scale_floor=0.1、open_penalty=2、extend_penalty=0.5、其余惩罚为 0、power=2、k-medoids、k=6 作为下一步的起点。对应 [baseline 诊断](1119_35/diagnose.html) 和 [challenge 诊断](1119_37/diagnose.html)。这些数值需要在命令中填写，程序没有隐藏的参数模式。

challenge 的 ARI 从原流程的 0.0086 提高到 0.1753，纯度从 26.2% 提高到 44.3%，早晚峰共簇率从 87.5% 降到 5.7%；但最近邻同类型比例从 48.4% 降到 41.0%。因此不能说所有指标都改善了，也不能认为困难数据已经聚好了。后续应使用已有单因素 sweep 检查幅度、噪声、缺失和时间形变各自的影响，再用未参与选择的数据检验稳定性。

实现验证：20 项自动测试通过；诊断网页脚本语法检查通过；新报告的预处理、距离矩阵和匹配路径保持一致。原有 demo、1119_01～1119_26 及其报告没有被改写。
